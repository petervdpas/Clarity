# Clarity.Ui

Clarity.UI for C# (DESIGN 7.9): the thin C# layer over the one Clarity.UI library, written in Rust (`clarity-ui`) and called through its C interface (`clarity_ui.h`, built from `runtimes/rust-ui-ffi`). The library draws the windows of an application generated by [Clarity](https://github.com/petervdpas/Clarity), lays them out, takes what the person does and runs the desktop host. The application keeps its window model in C# (`Clarity.Runtime`: view models, part states, undo, records, handlers) and answers the library.

## What a generated program calls

```csharp
DesktopWindow.Run(new MainViewModel(databases));
```

`DesktopWindow.Run(Unconnected, Text)` starts a program whose databases did not open (DESIGN 5.27). With the environment variable `CLARITY_HEADLESS` set, the library drives the program from standard input instead of showing a window (DESIGN 1.6).

## Custom parts

A custom part derives from `CustomPart` and names its kind with `[PartKind("Gauge")]`. It draws on the library's canvas through `Painter` (fill, stroke, line, oval, SVG path, text, pixels, clip, the theme's colors by role) and takes the pointer, keys and the focus through its `On...` methods. `ChangeValue` changes what it binds, `Tell` runs the handler wired to a tell.

## The native library

The package carries the library for each system in `runtimes/<rid>/native/` (linux-x64, linux-arm64, win-x64, win-arm64, osx-x64, osx-arm64), as SkiaSharp carries Skia.

Working in Clarity's repository, build the library first, then the C# projects; each build copies the library of this system from `target/debug` (or `target/release` for a Release build) next to the program and test outputs:

```sh
cargo build -p clarity-ui-ffi            # target/debug/libclarity_ui.so (.dll, .dylib)
dotnet build runtimes/csharp/Clarity.slnx
```

A generated program built on the repository's projects (`dotnet build -p:ClarityRuntime=<repo>/runtimes/csharp`) finds it the same way.
